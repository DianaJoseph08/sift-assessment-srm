SIFT — Technical Documentation

System Architecture, Security Safeguards & Database Engineering

1. Technology Stack Overview

SIFT is constructed as a lightweight, robust, single-port deployable web application comprising a modern Single Page Application (SPA) frontend and a RESTful backend server.

Layer Technology Description
Frontend React.js (v18) + Vite Builds a fast, modern UI with flexible CSS variables and responsive views.
Backend Express.js (Node.js) Directs API endpoints, file uploads, AI adapters, and static client hosting.
Database SQLite3 Reliable file-based relational database stored locally at server/sift.db.
AI engine Ollama / Gemini / Claude Multi-provider adapter supporting local offline LLMs and cloud-based models.
Document Parsing pdf-parse & mammoth Extracts text profiles directly from uploaded PDFs and DOCX resumes.

2. Database Schema

The database uses SQLite to maintain persistence. The tables are configured with proper foreign key structures to handle candidates and their evaluations relative to define roles.

A. Jobs Table (jobs)

Stores the details of defined recruiter job openings.

CREATE TABLE jobs (
  id TEXT PRIMARY KEY,
  title TEXT,
  department TEXT,
  seniority TEXT,
  minYears INTEGER,
  location TEXT,
  mustHave TEXT,     -- JSON array of must-have skills
  niceToHave TEXT,   -- JSON array of nice-to-have skills
  description TEXT,
  createdAt TEXT
)

B. Candidates Table (candidates)

Stores candidate resume evaluations, interview transcripts, and proctoring logs.

CREATE TABLE candidates (
  id TEXT PRIMARY KEY,
  jobId TEXT,
  candidateName TEXT,
  email TEXT,
  currentTitle TEXT,
  yearsExperience INTEGER,
  education TEXT,
  topSkills TEXT,      -- JSON array of top skills
  subScores TEXT,      -- JSON object of categorized scores
  overallScore INTEGER,
  recommendation TEXT,
  summary TEXT,
  strengths TEXT,      -- JSON array of strengths
  gaps TEXT,           -- JSON array of gaps
  missingMustHaves TEXT,
  interviewQuestions TEXT,
  interviewFocus TEXT,
  fileBase64 TEXT,
  filename TEXT,
  status TEXT DEFAULT 'Applied',
  interview TEXT,      -- JSON object containing transcript & proctoring metrics
  createdAt TEXT,
  FOREIGN KEY(jobId) REFERENCES jobs(id)
)

3. Proctoring & Security Architecture

To guarantee academic integrity and prevent candidates from utilizing external resources (like ChatGPT) during mock assessments, SIFT employs browser-level sensors coupled with deterministic backend validation overrides.

Fraud Penalization Policy: If a candidate switches tabs even once or copy-pastes any response into the chatbox, the backend automatically overrides their technical score, capping it at a failing grade of 30%.

A. Client-side Focus & Clipboard Listeners

The candidate portal registers window blur events to detect tab switching, and paste events to detect clipboard copy-pasting:

// App.jsx Focus Loss Monitor
window.addEventListener("blur", () => {
  setTabSwitches(prev => prev + 1);
  setShowWarning(true);
});

// App.jsx Copy-Paste Monitor
onPaste={() => {
  setPasteCount(prev => prev + 1);
}}

B. Backend Score Overwrite Enforcer

Before saving the evaluation to the database, SIFT's Express server inspects the proctoring logs. If cheating is caught, it caps the score and prepends an audit alert to the summary:

function enforceProctoringOverride(evaluation, proctoring) {
  if (!proctoring) return evaluation;
  const { tabSwitches, pasteCount } = proctoring;

  if (pasteCount > 0 || tabSwitches > 0) {
    evaluation.score = Math.min(evaluation.score || 0, 30);
    evaluation.summary = `[PROCTORING ALERT: Serious fraud detected. Candidate completed the assessment with ${pasteCount} copy-paste actions and ${tabSwitches} tab switches. The technical score was automatically overwritten to fail.] ` + evaluation.summary;
  }
  return evaluation;
}

4. Voice Discussion System (STT & TTS)

SIFT features a built-in voice discussion suite to simulate real-world interactive speech assessments without loading external plugins.

Browser Native: Web Speech engines run locally inside the candidate's browser, utilizing Google Chrome or Microsoft Edge's speech components.

A. Speech-to-Text (Voice Typing)

Utilizes the browser's SpeechRecognition parser. Chunks of recorded audio are converted to text and appended in real-time into the text input value:

const SpeechRecognition = window.SpeechRecognition || window.webkitSpeechRecognition;
const recognition = new SpeechRecognition();
recognition.onresult = (event) => {
  const resultText = event.results[0][0].transcript;
  setInput(prev => prev + " " + resultText);
};

B. Text-to-Speech (Read Aloud)

Utilizes window.speechSynthesis. Under every AI interviewer bubble, a manual 🔊 Listen button is provided. Clicking this button activates a user-initiated speech utterance that reads the text aloud, successfully bypassing browser media autoplay blocks.

5. AI Model Integration & Adapters

The system uses a modular controller inside server/analyze.js to connect seamlessly to different LLM models based on environment variables:

  • Local Ollama (Offline): Communicates with local daemon on http://localhost:11434/api/chat.
  • Google Gemini API (Free Cloud): Dispatches requests using standard HTTP POST requests to gemini-2.5-flash.
  • Anthropic Claude API (Premium Cloud): Leverages the official SDK to request evaluations from claude-3-5-sonnet.

All adapters require the model to respond strictly with valid JSON conforming to SIFT's standardized schemas to ensure smooth database logging.
